# 关系型数据库 vs 知识图谱效果对比方案

## 1. 问题定义

你当前的核心问题是：**把关系型数据库转成知识图谱到底带来什么价值**，以及在你的业务场景下，两种方法谁更有效。

本方案用于做可复现实验，对比：

- 方案A：直接使用关系型数据库（SQL）
- 方案B：将关系型数据库转为知识图谱（RDF/TTL + 图查询）

---

## 2. 转换为知识图谱的作用（对比维度）

重点不在“能不能查到数据”，而在以下能力是否提升：

1. **语义表达能力**：字段含义（label/comment）是否可显式表达。  
2. **关系建模能力**：跨表关系是否更自然（尤其多跳关系）。  
3. **可解释性**：查询结果是否能给出更清晰的语义依据。  
4. **可扩展性**：后续接入新数据源/新本体是否更平滑。  
5. **智能问答友好性**：对自然语言查询与 LLM 推理是否更友好。

---

## 3. 实验目标与假设

## 3.1 目标

量化比较 SQL 与 KG 在真实查询任务中的：

- 准确性
- 时延
- 查询复杂度
- 可解释性

## 3.2 假设

- H1：简单单表聚合查询中，SQL 速度更快。  
- H2：多跳关联与语义模糊查询中，KG 更易表达且可解释性更高。  
- H3：结合术语语义（label/comment）时，KG 在自然语言问答任务中准确率更高。

---

## 4. 对照实验设计

## 4.1 数据与环境

- 同一数据源：`data/company/poi.sqlite`
- 图谱数据：由当前流程生成的 `data/ttl/poi.ttl`
- 保持同一硬件、同一轮次、同一查询集

## 4.2 查询任务集（建议 40~80 条）

按难度分层：

1. **基础查询（20%）**：单表筛选、排序、统计  
2. **关联查询（40%）**：跨表连接、条件组合  
3. **语义查询（30%）**：同义词/业务口径问题（如“地址”“备注”）  
4. **多跳与解释（10%）**：要求返回路径或语义依据

每条任务都准备：

- 自然语言问题
- SQL 标准答案（Gold）
- KG 预期答案（Gold）

---

## 5. 评估指标

## 5.1 结果质量

- **Answer Accuracy / F1**：结果与 Gold 的一致性
- **Top-k Hit Rate**（若返回候选）

## 5.2 性能

- 平均响应时间
- P95 响应时间
- 失败率（语法错/空结果/超时）

## 5.3 工程复杂度

- 查询编写长度（SQL/SPARQL token 数）
- 新增一个查询需求的改造时间

## 5.4 可解释性（人工评分 1~5）

- 结果是否可溯源到字段语义
- 是否能解释“为什么是这个字段/关系”

---

## 6. 执行流程

1. 构建基准问题集（含 Gold）  
2. 分别执行 SQL 路径与 KG 路径  
3. 记录结果、时延、错误类型  
4. 进行人工可解释性评分  
5. 汇总统计并出对比结论
