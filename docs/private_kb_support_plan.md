# 私域知识库与无知识库双模式改造方案（审阅版）

## 1. 目标

让项目支持两种工作模式：

1. **私域知识库模式（启用检索增强）**：当提供私域知识库时，先构建/加载向量索引，再进行检索增强。  
2. **纯模型推断模式（禁用检索增强）**：当未提供私域知识库时，不做向量检索，完全依赖模型根据表结构与样本值推断属性和关系。

## 2. 当前问题

当前代码将 `Schema.org` 写死在流程中：

- `main.py` 强依赖 `schema_file` 参数与 `parse_schema_org`。
- `vector_store.py` 中 `OntologyVectorStore` 的构建语义默认以 Schema.org 术语为中心。
- `agents.py` 的提示词和 `_get_rag_context` 默认存在本体检索上下文。

这导致：

- 无法无缝切换到私域知识库；
- 无知识库场景下仍被迫走“本体检索”路径。

## 3. 总体设计

### 3.1 引入“知识源模式”

新增统一模式开关（由入口参数决定）：

- `knowledge_mode = "private_kb"`：提供私域知识库文件时启用。
- `knowledge_mode = "none"`：未提供知识库时启用。

### 3.2 统一术语结构

将知识条目统一为内部结构：

```python
{
  "uri": str,
  "type": str,
  "label": str,
  "comment": str,
  "domain": str,
  "range": str
}
```

字段说明：

- `uri`：术语唯一标识，用于最终映射输出与图谱引用。
- `type`：术语类别（类/属性/关系），帮助模型区分语义角色。
- `label`：术语名称，是检索召回与匹配的核心关键词。
- `comment`：术语说明，补充语义上下文，减少歧义。
- `domain`：术语适用主体范围，辅助判断字段属于哪类实体。
- `range`：术语值类型/目标类型，辅助区分数据属性与对象关系。

无论来自 Schema.org 还是私域知识库，最终都转换成同一结构，复用向量检索逻辑。

## 4. 文件级改造计划

## 4.1 `schema_parser.py`

- 保留现有 `parse_schema_org`（兼容历史）。
- 新增通用私域解析函数（例如 `parse_private_kb(file_path)`）。
- 私域解析器职责：
  - 读取私域知识文件；
  - 转换为统一术语结构列表；
  - 对缺失字段给默认值（如 `label` 回退到 `uri`，`comment` 默认为 `No description.`，`domain/range` 默认为 `None`）。

> 备注：第一版优先支持 JSON（数组对象）格式；后续可扩展 JSONL/CSV。

## 4.2 `vector_store.py`

- 将向量库语义从“Ontology/Schema 专用”改为“通用知识库”。
- 保持现有嵌入模型逻辑不变（QwenEmbeddings + Chroma）。
- 改造点：
  - 支持“可选启用”的向量库初始化；
  - 在无知识库模式下不构建向量索引；
  - `search()` 在未启用向量库时返回空结果（不抛异常）。

## 4.3 `agents.py`

- `_get_rag_context`：
  - 当向量库可用时，执行检索并拼接上下文；
  - 当向量库不可用时，返回空上下文并跳过检索日志。
- `run_mapping_agent` / `run_validator_agent` 提示词补充“模式感知”规则：
  - 有知识库：优先利用检索结果；
  - 无知识库：仅基于列名、样本值、表语义进行推断。

## 4.4 `main.py`

- 调整入口参数：
  - 将 `schema_file` 从“必填”改为“可选”；
  - 新增私域知识库参数（建议 `--kb-file`）。
- 启动逻辑：
  - 若传入 `--kb-file`：解析私域知识库并构建/加载索引；
  - 若未传入：不初始化索引，进入纯模型推断模式。
- 保持后续流水线（mapping/relation/validator/graph）接口不变。

## 5. 运行行为（改造后）

### 5.1 提供私域知识库

1. 解析私域知识条目；
2. 构建/加载向量索引；
3. 每列检索相关术语作为 RAG 上下文；
4. Agent 基于“表指纹 + RAG”做映射与关系推断。

### 5.2 未提供知识库

1. 跳过索引构建与检索；
2. Agent 基于“表指纹 + 样本值 + 列名语义”直接推断；
3. 继续输出映射、主外键（或推断关系）并构建图谱。

## 6. 兼容性与风险控制

- **向后兼容**：保留旧 Schema.org 解析函数，不破坏已有调用。
- **最小侵入**：尽量不改动 `graph_builder.py` 对下游结构的依赖（`mapping`、`pk/fks`）。
- **容错**：无知识库模式下确保不会因为 `search()` 或索引缺失而报错。

## 7. 验证计划（实施后执行）

1. 语法检查：`python3 -m py_compile`（受改文件）。
2. 功能验证 A（私域知识库模式）：确认检索结果被注入提示词并可正常出图。
3. 功能验证 B（无知识库模式）：确认全流程不依赖向量库也可跑通并产出 TTL。
4. 回归验证：现有数据库样例流程可运行。
