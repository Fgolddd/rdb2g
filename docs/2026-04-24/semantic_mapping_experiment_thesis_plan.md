# 基于《A Multi-Agent System for Semantic Mapping of Relational Data to Knowledge Graphs》的系统完善与硕士论文方案

## 1. 研究背景与目标

本项目参考论文《A Multi-Agent System for Semantic Mapping of Relational Data to Knowledge Graphs》，核心目标是将关系型数据库自动映射到知识图谱，并在多领域数据集上验证方法有效性。  
当前项目已具备多智能体映射、图向量检索、TTL构图和RDB/KG对比评测能力，后续重点是：  

1. 完善实验设计与评估闭环；
2. 系统化开展消融与跨域验证；
3. 形成可复现、可答辩的硕士论文成果。

---

## 2. 系统完善建议（结合当前代码）

### 2.1 已实现能力（与论文对齐）

- **Graph-Vector Store**：`schema_parser.py` + `vector_store.py`
- **多智能体协同**：`agents.py`（Mapping / Relation / Validator）
- **RDB->KG构图**：`graph_builder.py` + `main.py`
- **RDB vs KG评测**：`run_rdb_kg_eval.py` + `run_full_experiment.py`

### 2.2 建议优先增强模块

1. **评测指标标准化**
  - 增加列级映射准确率、关系识别P/R/F1、图级质量指标；
  - 输出统一评测报告（CSV + JSON + 图表）。
2. **可解释与可控增强**
  - 增加候选术语评分记录；
  - 增加拒识策略（低置信度时返回null而非硬映射）。
3. **鲁棒性与泛化能力实验**
  - 缺失显式PK/FK约束场景；
  - 跨域（Spider多domain + 企业私有数据）验证。

## 3. 实验步骤方案

## 3.1 研究问题（RQs）

- **RQ1**：多智能体是否显著优于单智能体？
- **RQ2**：RAG检索是否显著提升映射质量？
- **RQ3**：Validator对最终结果是否有稳定增益？
- **RQ4**：在缺少显式主外键时，系统鲁棒性如何？

## 3.2 数据与任务定义

### 数据集

- 主数据：Spider（论文一致）
- 外部验证：项目中的企业数据（如 `data/company/*.sqlite`）

### 任务拆分

- **T1 列级语义映射**：Column -> schema term
- **T2 关系识别**：PK/FK识别（含隐式推断）
- **T3 KG构建质量**：三元组正确性与词表合规性
- **T4 端到端可查询性**：RDB/KG查询成功率与时延

## 3.3 对照组与消融组

建议至少设置以下实验组：

1. **B0 规则基线**：字符串/规则匹配（无LLM）
2. **B1 单Agent-无RAG**
3. **B2 单Agent+RAG**
4. **M1 多Agent-无Validator**
5. **M2 多Agent+Validator（完整系统）**
6. **M3 多Agent+私域KB**

关键消融：

- 去掉RAG
- 去掉Validator
- 去掉Relation Agent
- 仅列名 vs 列名+样本值
- 样本数K（1/3/5）敏感性分析

## 3.4 评价指标

### 映射层指标

- Top-1 Accuracy（列级）
- Macro-F1（按domain）
- Coverage（非null映射比例）
- 置信度校准一致性（HIGH/MEDIUM/LOW vs 人工正确率）

### 关系层指标

- PK识别准确率
- FK识别 Precision / Recall / F1

### 图层指标

- Triple-level Precision / Recall / F1（抽样人工标注）
- 词表合规率（Schema/私域KB term命中率）

### 端到端指标

- Query Success Rate（RDB/KG）
- 延迟（平均值 + P95）
- 错误类型分布（mapping error / relation error / query error）

## 3.5 实验流程（可复现）

1. 固定模型与参数：模型版本、温度、prompt版本、embedding模型。
2. 固定数据划分：按domain划分训练/验证/测试或按论文划分方式。
3. 对B0~M3逐组运行并保存中间产物：
  - `mapping.json`
  - `relations.json`
  - `ttl`
  - `eval_*.csv`
4. 人工标注子集（建议10~20个数据库）进行质量校验。
5. 统计分析：显著性检验（t-test/bootstrap CI）。
6. 输出论文图表与案例分析。

## 3.6 风险与应对

- **LLM波动**：固定温度=0，必要时多次采样取众数。
- **人工评测主观性**：双人标注 + Cohen’s Kappa。
- **外部Neo4j不稳定**：保存离线TTL与本地复算脚本。
- **提示词过拟合**：固定prompt版本，不在测试集调prompt。
